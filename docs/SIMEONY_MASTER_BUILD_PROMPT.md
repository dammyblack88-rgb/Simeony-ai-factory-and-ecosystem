# SIMEONY — MASTER DEVELOPMENT PROMPT

## Product identity
Product: SIMEONY
Studio: SimeonJr Studios
Slogan: Build beyond imagination.

Build SIMEONY as an independent, commercial-grade AI-powered universal creation platform.

## Vision
Users describe an idea in natural language. SIMEONY helps plan, build, test, preview and evolve the resulting digital product. Long-term creation domains include websites, SaaS, APIs, databases, CRM/ERP, enterprise apps, e-commerce, mobile and desktop apps, AI agents, automation, 2D/3D games, simulations, 3D assets, animation, cinematics and VFX.

Do not promise that one prompt can instantly produce every complex product. Support iterative, multi-stage creation with clear progress and human approvals.

## User modes
- SIMPLE: guided creation for nontechnical users.
- STUDIO: professional control over stack, files and workflows.
- EXPERT: advanced planning, integrations and multi-agent projects.

## Architecture

### 1. Control Centre
Accounts, workspaces, dashboard, projects, settings, usage, history, versioning and previews.

### 2. Intelligence
Request understanding, requirements, planning, task decomposition, scheduling, agent adapters, retries, progress, logs and approval checkpoints.

### 3. Creation Engines
Web/frontend, backend/API, databases, mobile, desktop, AI/automation, games/3D and media/creative tools.

### 4. Cloud Infrastructure
Isolated workspaces, build/test environments, storage, databases, deployment adapters, monitoring and backups.

## Creation lifecycle
1. Receive and classify the request.
2. Clarify essential missing requirements.
3. Produce a structured plan and acceptance criteria.
4. Break work into trackable tasks.
5. Select appropriate tools and engines.
6. Enforce permissions, safety and cost controls.
7. Prepare an isolated workspace.
8. Execute work through approved agents and tools.
9. Build, test and repair.
10. Present a working preview.
11. Obtain approval before consequential deployment.
12. Export or deploy only with permission.
13. Preserve history and support future iteration.

## SIMEONY ownership
SIMEONY must own its project lifecycle, task manager, orchestration, permission and approval system, workspace policies, integration interfaces, build/test workflow and user experience. External open-source projects are engines or adapters, not replacements for SIMEONY's identity or core orchestration.

## Current implementation milestone
Continue from the existing React + TypeScript + Vite foundation in this repository. Do not rebuild or discard it.

Build a polished, responsive product foundation with:
- SIMEONY control-centre shell and navigation.
- Dashboard and project creation flow.
- Simple, Studio and Expert modes.
- Persistent project/task data (choose a safe, maintainable approach).
- Project details, task list, status and activity history.
- Clear integration boundaries for future AI agents.
- Accessible responsive UI, useful empty states and error handling.
- Tests and build verification.

The existing UI is only a foundation. Do not represent placeholder actions as working AI generation. Clearly label integrations that are not connected.

## Engineering requirements
- Prefer TypeScript and modular, maintainable code.
- Validate all input and isolate user/workspace data.
- Never expose secrets or API keys in browser code.
- Add authentication and authorization before private user data is exposed.
- Add tests for meaningful behavior.
- Document setup, architecture and commands.
- Keep the project compatible with GitHub Codespaces.
- Avoid unnecessary dependencies and paid services.
- Do not create paid resources, incur charges, enable billing or deploy without explicit user approval.
- Preserve existing files and data. Avoid destructive changes.
- Do not claim tests, deployments or integrations succeeded unless verified.

## Open-source integration policy
Evaluate foundations such as OpenHands, Dyad, Bolt.diy, Appsmith, Refine, Coolify, Blender, Godot, GDevelop, Bevy, Three.js, Babylon.js, PlayCanvas, Flutter, React Native and Tauri only when they serve a defined need.

For every integration, review licence, compatibility, maintenance, security and operational costs. Use clean adapters. Do not blindly clone, bundle or compile every engine. Large creative engines remain optional integrations.

## Autonomous working method
Do not stop after writing plans or documentation. Work through the highest-priority safe implementation task:
1. Inspect current code and status.
2. Make a focused change.
3. Run type checks, tests and production build.
4. Fix failures.
5. Update status and explain what is genuinely complete.
6. Continue until blocked by missing credentials, required user decisions, resource limits or approval.

Do not fabricate functionality or test results. Ask the user only for essential decisions or permissions.

## Immediate objective
Continue building the existing SIMEONY application foundation. Make the first milestone genuinely usable, then progress toward real persistence, authentication, AI provider adapters, agent orchestration, isolated execution, creation engines, preview, testing and deployment workflows. Keep SIMEONY independent from unrelated projects.
